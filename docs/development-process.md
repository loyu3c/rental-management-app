# 規格驅動開發流程

採用類似OpenSpec的輕量流程；目前未安裝OpenSpec CLI，不能宣稱已導入該工具。

## 正式規格

requirements.md、tenancy-and-parking.md記錄業務規則；mobile-design.md為畫面與模型草案；[UI 與功能架構開發規範](ui-architecture-guidelines.md)為後續畫面與互動的必遵循基準（2026-10-17 確認），舊版配置若衝突以此規範為準。變更以最新明確使用者決定為準，衝突時先更新規格。

## 每項變更

在 docs/changes/<功能名>.md 記錄：
1. 要解決的問題、範圍與不含項目。
2. 畫面及資料影響，包含舊資料相容與更新方式。
3. 可勾選開發任務。
4. Given/When/Then驗收案例與實際測試結果。
5. 已知限制、完成狀態與對應commit。

流程：規格→任務→coding→review→驗收→更新完成紀錄。一般實作選擇由開發者決定；需要改變業務行為或由使用者選擇的視覺方案先討論。並非每個commit都要求使用者批准。

## UI 變更必讀與檢查

新增功能或調整畫面前，先讀 [UI 與功能架構開發規範](ui-architecture-guidelines.md)，在變更文件標明入口、頁籤、按鈕、返回行為與遷移狀態，交付前逐項完成該文件的驗收檢查。既有不一致畫面逐步遷移，不能繼續沿用為新功能的範本。一般符合規範的實作不需重複詢問；需要偏離時記錄原因並先討論。純文件變更核對內容與連結即可，不要求產出 APK。

## Review檢查

由GPT統一開發並另行檢查差異、金額計算、重複入帳、租約隔離、起算餘額、同步重試、憑證位置、升級與資料保存。此為同一開發者自我審查，不宣稱獨立Claude review。

## 完成條件

- 已實作驗收行為，相關測試與Android lint通過。
- GitHub Actions編譯成功、APK已存在；CI成功不代表已實機驗證。
- 正式可記帳版本需備份/還原及固定簽署更新驗證。
- 未完成的Google同步、拍照與語音明確顯示未啟用；不以假成功替代。

## 當前狀態

0.5.0-preview 已加入暖色分層建檔、租約、帳單、抄表、年繳與合併收款及完整備份；固定簽署 APK、帳務測試與 lint 已通過 GitHub Actions。實機操作及覆蓋保留資料更新尚待驗證；Google、拍照、語音、支出、押金收付仍未啟用。

## 2026-11-26：後續修改與 APK 交付

使用者已授權後續 App 功能修改完成、相關檢查通過後，直接合併並發布可安裝 APK，不必每批重複詢問是否發布。

- 沿用 applicationId `com.loyu3c.rental.preview` 與既有固定簽署金鑰，遞增 versionCode 與 versionName；設定頁顯示實際安裝版本。
- 交付為原 App 的覆蓋更新，保留帳務、附件與設定，不另建 App；不得要求先解除安裝以解決簽章問題。
- 發布前檢查舊資料相容、相關單元測試、Google 同步契約測試、Android lint 與 release 建置。
- 沿用 tag 觸發的 Release APK 流程，確認 APK 已上傳，且簽章憑證指紋與前版相符，再提供下載連結。
- 覆蓋安裝與資料保存的實機驗證若尚未執行，須如實註明，不把 CI 通過當成實機驗收。
- 安裝前建議先從設定匯出完整備份。若簽章不符則停止更新並調查，不引導解除安裝。
