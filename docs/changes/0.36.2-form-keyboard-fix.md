# 0.36.2-preview：表單無法叫出鍵盤修正

使用者實機回報新增物件、帳單、租約、支出可顯示游標但不能輸入。優先修復輸入，第三批 UI 工作暫緩。

## 原因與修正

共用 FullFormDialog 繼承 AlertDialog，在 super.onCreate 判斷輸入能力後才替換內容；系統可能保留 FLAG_ALT_FOCUSABLE_IM。僅設定 ADJUST_RESIZE 不會解除輸入法阻擋。

- 共用全頁表單建立與啟動時清除 ALT_FOCUSABLE_IM／NOT_FOCUSABLE，保留鍵盤縮放。
- 租約與支出全頁 Dialog 及開啟編輯器的查詢頁一併套用輸入視窗設定。
- 一般文字欄位明確啟用文字輸入、觸控焦點與軟鍵盤，點擊後以 SHOW_IMPLICIT 請求鍵盤；日期欄位仍覆寫為選擇器，不開放手打。
- 模擬器另抓出帳單即時合計使用送出驗證，在另一欄空白時 fieldError 會 requestFocus，導致正在輸入的數字被導向其他欄位。新增不改焦點／錯誤狀態的 previewAmount，套用帳單即時合計與支出分攤合計；按核對才執行原驗證。
- 金額數字限制、已開單欄位鎖定、取消草稿、防重複入帳與附件流程保持原規則。

## 驗證

- [x] 原有 JVM 帳務與 Google 同步測試、Android lint、固定簽署 APK。
- [x] API 35 模擬器：實際開啟新增不動產、建立帳單、新增租約、新增支出，點可編輯欄位，確認輸入法視窗出現，再發送字元確認欄位收到文字。
- [ ] 使用者 Samsung Android 16 實機覆測。

新增 Android Form Input Regression workflow。測試只用模擬器的測試資料，不確認或保存任何交易，也不連 Google。

編譯通過不等於輸入驗證完成；交付需另確認模擬器結果，若受測試環境限制必須明示。

## 實際結果

- 初輪模擬器測試 3/4 通過，帳單只收到第一個字元；保留診斷等待後仍失敗，證實不是單純測試等待不足。進一步定位為預覽計算呼叫 fieldError 搶走焦點。
