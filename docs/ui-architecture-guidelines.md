# UI 與功能架構開發規範

確認日期：2026-10-17（Asia/Taipei）。

本文件是後續新增功能、修改畫面與操作驗收的共同規範。既有畫面逐步遷移；列出的目標架構不代表目前 APK 已全部完成。過去版本紀錄保留為歷史；畫面配置有衝突時以本規範及最新明確使用者決定為準。UI 整理不得自行改變帳務、租約或分享權限規則。

## 核心原則

底部選主要工作、頁籤切換同層資料、點卡片看內容、右上角「⋯」處理單筆操作、表單底部完成新增或修改。同一資料只有一套詳情與編輯流程，多個快捷入口應開啟同一畫面。

## 目標功能架構

| 底部入口 | 第二層 | 功能歸屬 |
|---|---|---|
| 首頁 | 不設頁籤 | 本月摘要、待收款、待開單、租約到期、待結算；摘要可連往原功能 |
| 收租 | 應收帳務／收款紀錄 | 租約應繳狀態、建立帳單、收租、歷史收款 |
| 記帳 | 支出／轉帳／帳戶 | 支出、照片憑證、提款轉帳、帳戶流水與對帳 |
| 不動產 | 物件／房東 | 建物土地、出租單位、租約、房東資料與不動產／帳戶歸屬 |
| 報表 | 房東／租客／管理總覽 | 房東月報、租客專屬報表、支出分攤、押金與退租統計 |

設定入口統一在主要頁面右上角齒輪，集中 Google 設定／測試、備份／還原、支出類別、舊資料整理。報表以查詢與分享為主；押金收退、退租等交易操作回到對應租約。保留必要快捷，但不得另建一套流程。

## 租約詳情

不動產與收租入口開啟同一租約詳情，固定四頁籤：

| 頁籤 | 內容 | 常用動作 |
|---|---|---|
| 概況 | 租客、租期、計價、繳款週期、租金、待繳摘要 | 收到租金 |
| 帳務 | 帳單、收款、抄表紀錄 | 建立帳單、記錄電表 |
| 押金／結算 | 約定與實收押金、收退紀錄、退租費用 | 收到押金、退還押金、辦理退租 |
| 附件 | PDF 合約、起始電表照片 | 新增／更換附件 |

右上角「⋯」提供修改租約、租客報表與分享等次要操作。可用動作仍由已入帳、已退租等業務狀態決定。

## 操作與按鈕

| 操作 | 固定位置與行為 |
|---|---|
| 返回 | 左上角返回箭頭及系統返回都回實際來源，保留列表搜尋、篩選、頁籤與位置；不得固定寫返回不動產 |
| 新增 | 列表右上角「＋ 新增」；明確上下文可寫新增支出／租約 |
| 查看 | 點卡片進詳情，以「›」提示；卡片內按鈕不得誤觸卡片導航 |
| 單筆操作 | 卡片／詳情右上角「⋯」，依實際能力列修改、修改紀錄、撤銷等 |
| 搜尋／篩選 | 列表上方搜尋欄，旁放篩選／排序；明示目前條件與重設入口 |
| 展開明細 | 區塊下方靠左「明細 ⌄」，展開改上箭頭，保留清楚狀態 |
| 編輯表單 | 固定底部左「取消」、右「儲存」；主要動作同時只強調一個 |
| 金流表單 | 底部「核對」，確認頁用具體文字如「確認入帳」；尚未確認不保存交易 |
| 撤銷 | 放「⋯」內，紅色文字並確認；依業務需要保留原因與歷史 |
| 設定 | 主要頁面右上角齒輪，不混入報表列表 |

位置一致不代表所有紀錄都必須可修改。只支援撤銷重登的資料不得因 UI 統一而新增無追蹤的覆寫。查看型頁面用返回；取消用於編輯或選擇，勿混用。停用出租、撤銷交易、停止分享必須分別命名，不統稱刪除。

## 表單、列表與附件

- 新增／修改採全頁、相同欄位順序、緊湊分組；彈窗留給簡短選擇與確認，避免多層彈窗。
- 避免大量外框、過寬留白與過高欄位。保留固定欄位名稱；長說明收合，不能只用 placeholder 當標籤。
- 固定操作列不得遮住欄位；小螢幕、鍵盤開啟及大字體均可捲動完成。離開有變更的草稿須避免無聲遺失。
- 支出列表首行日期與金額，下一行項目內容；分類與付款帳戶在左、照片縮圖靠右，分攤明細在下方靠左。長文字可換行，不擠掉金額及操作。
- 歷史版本包含該版本照片與文字；已撤銷紀錄灰色／刪除線搭配狀態文字，保留查閱。
- 附件統一一列：左縮圖／PDF 圖示，中間名稱與狀態，右「⋯」提供更換／移除；點縮圖或檔名查看。
- 沒有附件時顯示「＋ 新增照片」或「＋ 選擇 PDF」。表單內先選附件，最後一起儲存；取消選檔不清除舊附件，取消表單不提交變更。
- 不再以「儲存並選 PDF」或關閉表單作為選附件前置步驟。相機、相簿與檔案返回後保留欄位和捲動位置。
- 新增或修改成功即時刷新相關列表、詳情與摘要；本機保存與 Google 報表更新狀態分開呈現。

## 圖示、顏色與文字

採同一套線條 vector 圖示，延續暖色設計；不要混用不同風格或以 emoji 當正式 UI 素材。常用操作搭配短文字，只有返回、更多、設定等熟悉圖示可獨立使用，且需無障礙名稱。

| 功能 | 圖示語意 |
|---|---|
| 新增／修改 | 加號／鉛筆 |
| 修改紀錄 | 歷史時鐘 |
| 照片／合約 | 相機或圖片／PDF 文件 |
| 分享／同步 | 分享／循環箭頭，兩者不可混用 |
| 對帳／啟停出租 | 核對／開關 |
| 更多／撤銷 | 三點／取消圖示 |

圖示視覺可小，觸控區至少 48dp；提供按壓回饋。出租綠燈、未出租灰燈必須搭配文字，停用另標「停用」，不得只靠顏色判讀。金額使用千分位。錯誤指向具體缺漏欄位，保留已輸入內容。

## 開發與驗收

每次 UI 變更的 docs/changes 文件必須記錄所屬入口、頁籤、主要／次要按鈕、返回來源、適用規則及未完成遷移項。優先重用共用元件；不要在各頁複製不同的選單、操作列或附件流程。

交付前逐項核對：

- 新功能符合既定歸屬；多入口使用同一詳情與表單。
- 新增、查看、更多、搜尋、返回與底部操作位置一致。
- 常用動作直接可達，次要操作收進「⋯」，無無意義的中間選擇。
- 不同入口返回正確，頁籤、搜尋與列表狀態保留。
- 長標題、長 PDF 檔名、無照片、多照片、小螢幕、大字體及鍵盤情境可操作。
- 取消、附件返回、修改、撤銷、分享失敗及重試不遺失資料或重複入帳。
- 原帳務計算、歷史追蹤、資料隔離、備份與授權規則保持正確。
- 記錄實際驗證與限制，不將規範或 CI 通過宣稱為已完成實機驗收。

純文件更新只核對內容與連結，不要求為此編譯 APK。實作變更依影響執行有意義的測試、lint 與建置。

## 遷移順序（尚待實作）

1. 整合租約詳情、各類紀錄的「⋯」與表單底部操作。
2. 整理五大入口、第二層頁籤及設定歸屬。
3. 統一附件、搜尋篩選、圖示、間距與返回狀態。

每批完成後更新版本紀錄；不得把上述遷移計畫當成已完成的 App 功能。
